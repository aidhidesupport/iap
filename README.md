# IAP — Interaction Accommodation Protocol

**対話・協働の条件調整プロトコル**

維持・編集：[@aidhidesupport](https://github.com/aidhidesupport)  
状態：0.2-draft / 2026-09-18

IAPは、仕事の目的・完成条件・連絡方法・中断と再開の条件を文章で明確にし、本人の意思を保ちながら相手やツールと協働するための仕様草案です。最初の適用例は、文章で依頼を受け、成果物を返す小さな開発案件です。

作業途中に自分でずれに気づくことだけに依存せず、観測・確認・復旧を作業の仕組みに入れることを目指します。発達特性のある人の困りごとを出発点としていますが、診断の開示やIQを利用条件にする設計ではありません。

## 読む順序

まず [短い導入手順](QUICKSTART.md) から、一つの架空案件で流れを確認できます。

1. [統合仕様 0.2](IAP_SPEC.md)：設計原則、要件、状態遷移、LLMの位置付け、権限、運用、未決事項。
2. [最初の1案件の試用手順](PILOT_RUNBOOK.md)：小さな案件で、手戻りと対応負担を測る手順。
3. [適合・反証ケース](CONFORMANCE_CASES.md)：初期の検証案。実装済み・試験済みを意味しません。

## 現時点でできていること

- 仕様草案と、失敗した場合の扱いを含む検証ケース。
- 別途開発中の1ブラウザ・1案件の試用実装：確認案の版管理、確認時刻、根拠の記録、中断・再開、時間記録、バックアップ。
- [エージェントによる模擬試行](PILOT_RESULTS_2026-09-18.md)：目的から外れた途中成果の照合、中断・復元、CSV画面の完成までを確認。利用者での効果実証とは区別しています。

今後の実装順序と完了条件は [ROADMAP.md](ROADMAP.md) にまとめています。

試用実装は、相手の認証を伴う共同編集、自動での作業成果取得、LLMによる逸脱の自動検知、課金には未対応です。利用者での効果、支払意思、IAP全体への適合性はまだ検証していません。このリポジトリでは仕様草案を公開しています。アプリの提供開始を告知するものではありません。

## MCPとの関係

AIや異なるサービスが協働条件を交換できる仕組みを目指す構想です。現行MCPの公式拡張・公式標準ではなく、MCP実装や登録が完了したものでもありません。

## フィードバック

Issueで、曖昧な要件、実際には使えない手順、反証例を提案してください。小さな架空例で十分です。職場の原文、個人名、診断情報、顧客資料、資格情報は公開Issueへ投稿しないでください。

大きな改稿やコードの寄稿受付は、権利関係を整理するまで保留します。Issueで議論しただけで、その人の権利がプロジェクトに移る扱いにはしません。
