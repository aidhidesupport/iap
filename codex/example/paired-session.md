# PM・開発者の初回試用：開始用の記入用紙

未記入の雛形。参加者・案件・送信先は未定、共有・検収は未実施。普段の会話で決まった内容をCodexが記入する。人への途中確認は最大2回を目安とし、範囲内の修正・再確認は開発者側で進める。

## 開始前

| 項目 | 内容 |
|---|---|
| 案件・予定日時・時間上限 | 未定 |
| PM役／開発者役 | 未定／未定。別々の人 |
| 依頼の目的・渡す成果 | 未定 |
| 完成条件（観測できるもの） | 未定 |
| 対象外 | 未定 |
| 読む成果物・プロジェクト | 未定 |
| 作業記録の版 | 未定 |
| 共有する相手・既存の連絡経路 | 未定 |
| 返答の目安 | 未定。即答は求めない |
| 記録の保存先・期間・削除担当 | 未定 |
| 費用・成果物の利用条件 | 未合意 |

## 判断が必要な場合の記録

| 項目 | 内容 |
|---|---|
| 何を判断してほしいか・選択肢・影響 | 未設定 |
| 対象の契約版・成果の観測ID | 未設定 |
| PMへの判断依頼時刻 | 未実施 |
| PM本人の回答・回答時刻・出典 | 未回答 |
| 回答が指す範囲 | 未確認。目的変更／条件変更／範囲変更／成果の受け入れ等を区別 |
| 開発者が反映した変更・新しい版 | 未実施 |

これは手動の記録用紙。自動で回答を回収したり、承認を判定したりする機能ではない。回答後に成果や条件が変わった場合、古い回答を新しい成果の承認として使わない。

## 試用後に残すこと

- 開発者・PMそれぞれの確認時間、手戻り・誤警告への対応時間。
- 共有文の生成時間、手直し・送信操作・PMの読解時間、必要な判断の待ち時間。
- 開発者・PMそれぞれの「次も使うか」と理由。未回答は未回答のまま。
- 比較できる同程度の案件と根拠。なければ削減率を出さない。
